# ElderCareAI Implementation and Deployment Phase

The implementation and deployment phase prepares ElderCareAI for use by caregivers on a configured mobile build. The application brings account access, older adult profiles, synchronized health readings, care plans, alerts, the Elle assistant, and reports into one workflow. Its mobile client is an Expo SDK 54 and React Native application; Supabase provides authentication, data storage, realtime updates, and Edge Functions. Google Health supplies authorized wearable readings, while the care assistant calls Gemini through a server-side function.

Deployment is complete only when the mobile build, backend services, permissions, and user workflows have been checked together on a device. The repository contains development, preview, and production EAS build profiles and a separate static website with an administrator portal. These configurations describe how to prepare a release; this document does not assert that a public store release or production acceptance has occurred.

## Implementation Process

1. **Prepare the mobile application.** Install the project dependencies, set the public Supabase URL and publishable key for the selected environment, and use the existing app identifiers and `eldercareai` deep-link scheme. The mobile bundle must never contain a Supabase service-role key or the Google Health and Gemini secrets.
2. **Prepare account and data services.** Apply the repository's ordered Supabase migrations, configure Google sign-in and its callback URLs, and verify row-level access policies for caregiver and patient data. Configure the profile-photo storage bucket and the Realtime publication used by synchronized vitals.
3. **Deploy the server functions.** Set the Google Health OAuth and Gemini credentials as Supabase secrets. Deploy the Google Health authorization, synchronization, disconnect, and webhook functions, together with `ai-care-assistant`. Register the Google Health subscriber only after the webhook endpoint and required permissions are configured.
4. **Connect the caregiver workflow.** A caregiver signs in with Google, completes the caregiver and older adult profiles, connects Google Health or chooses to continue without it, and decides whether to allow phone location. The Home and Health screens then display synchronized readings when data is available. Care schedules, local reminders, alerts, reports, and Elle use the saved profiles and care data.
5. **Verify the integrated build.** Run the automated unit and integration suites and TypeScript check, then use an installed development or preview build for a device walkthrough. Confirm sign-in, onboarding, a new health synchronization, care-plan saves, reminder permission and delivery, PDF sharing, SOS confirmation, sign-out, and the empty states when no wearable data exists. Automated tests use controlled service doubles and do not establish live provider availability or device notification delivery.

## Deployment Procedure

The `development` EAS profile creates an internal development client. The `preview` profile is for an internally distributed build that can be installed and demonstrated on a phone. The `production` profile is configured for store-oriented builds. A successful cloud build alone does not prove that Google or Apple has accepted the application or that the target phone's integrations work.

1. Confirm that the target Supabase project, migrations, Edge Functions, OAuth redirects, Google Health consent, and app public settings belong to the same environment.
2. Build and install a fresh Android preview APK with `npx eas-cli@latest build --platform android --profile preview`. An APK already installed on a phone does not receive changes made later to the local `.env` file.
3. On the installed build, complete the device walkthrough using a test caregiver and patient. Verify the Google Health connection and the difference between a new wearable measurement and the time of the latest API check.
4. If publishing the static website, deploy the `website` directory as the site root. Deploy its `edcadmin` directory and public `config.js` only with the matching Supabase project. Validate administrator sign-in and role checks separately from the caregiver app.
5. Before a public release, replace the in-app demo Terms of Service and Privacy Policy text with reviewed content, test a release build on supported devices, verify permissions and report sharing, and retain a rollback path for backend and app changes.

## Installation Guide

1. Obtain the current ElderCareAI install link from the project team. For Android demonstrations, use the current preview APK generated by the `preview` EAS profile. Do not use an older APK after native permission or environment changes.
2. Install the application and open **ElderCareAI**. Keep an internet connection for Google sign-in and cloud data. Grant only the device permissions needed for the features you choose to use.
3. Tap **Sign in with Google** and use the caregiver account intended for Google Health access. Complete the caregiver and older adult information screens.
4. Tap **Connect with Google Health** and grant the requested scopes if wearable readings are needed. The app also offers **Skip for now**; without a connection, health readings remain empty until a later successful sync.
5. Select **Allow phone location** if you want the Last sync location feature, or **Continue without location**. The recorded point is the caregiver phone's location at a successful synchronization, not a live watch location.
6. In **Settings**, enable **Care notifications** if medication, appointment, and health alerts should appear on the phone. Test one non-emergency reminder after installation.

## Deployment Evidence to Retain

Keep the EAS build ID and install link, the migration and function deployment logs, and dated device screenshots of the user-guide screens. Record which test account and environment produced the evidence. Remove or hide real patient names, coordinates, contact details, and health measurements before placing screenshots in a public manuscript. For the figure-by-figure capture plan, use the companion screenshot checklist.
